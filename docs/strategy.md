# 通用的多模型省钱策略

策略与具体供应商无关。主会话选择能力足够的模型，角色按任务定义，不按品牌定义。主代理持有全局目标、规划和最终验收；低成本工作代理只接收相关材料、任务边界和验收标准。

## 先降低工作量，再降低单价

1. 确定性操作交给工具：搜索、格式转换、计数、编译、测试、重复检查。
2. 减少每次输入：只传必要片段和文件引用，避免每个子代理复制整段历史。默认 spawn 使用新上下文。
3. 分配清晰任务：资料提取、局部翻译、初稿、候选方案、已有测试可验证的小修改适合经济模型。
4. 保留主代理的判断：含糊需求、关键架构、复杂推理、跨任务冲突和最终综合仍由强模型负责。
5. 按风险决定审核：可直接运行测试的结果先靠测试；主代理能快速判断的结果不必再建立审核代理。独立审核需要付费，不能因为“监督”就忽略它的成本。

本插件提供角色委派、可选审核、有限返工和升级。它不强制拆分每项任务，也不自动判断一个模型是否足够强。模型审核是有误差的判断，必须结合证据和主代理验收。

## 按完整工作流比较

每次调用的估算费用为：

```text
C = (非缓存输入 × 输入单价
   + 缓存读取 × 读取单价
   + 缓存写入 × 写入单价
   + 输出 × 输出单价) / 1,000,000
```

所有单价使用同一种货币。推理用量已经包含在 DSH 的输出总量中。

整个任务必须计入：规划、所有工作代理、所有审核、返工、升级、主代理的综合与最终验收。并行能减少等待时间，但不会自动减少这些调用的总费用。

为便于估算，假设关闭额外初始模型返工（`qualityRetries: 0`），每个任务先用经济模型，审核失败后升级一次，升级结果也审核：

```text
C_baseline = C_main + n × C_strong
E[C_router] = C_main + n × [C_worker + C_review + q × (C_strong + C_review)]
```

`q` 是实际升级概率，而非模型自行报告的“置信度”。当其他条件相同时，要省钱需满足：

```text
q < (C_strong - C_worker - C_review) / (C_strong + C_review)
```

仅作为算术示例：主代理合计 0.5 单位、5 个任务、强模型每项 1 单位、经济模型 0.08、审核 0.03、升级率 15%。全部强模型约 5.5；上述委派方案期望约 1.8225，减少约 66.9%。这些数值是虚构的，不是任何模型的报价或实测节省承诺。上下文增加、返工、长输出或昂贵审核都可能消除节省。

启用更多返工时，应逐项累加每次实际调用，而不是套用一次升级的公式。若主代理为了监督需要大量重复阅读，则 `C_main` 也会增加。

## 配置方法

建议先选少数边界清楚的角色，设置 `qualityRetries: 0` 或 `1`，仅为需要的角色配置审核和升级。保留主代理的模型能力，先比较真实的费用、失败率和返工率，再扩大委派范围。

相同输入、相同验收标准下比较两种工作流。评估最终交付物的正确性和完整性，同时记录任务费用与用时。人工质量复核可以在本地进行；本版没有自动基准评测或宣称“零损失”的质量评分。

选择性委派、工具优先、精简上下文，通常比固定为所有任务增加“规划—执行—审核”三次模型调用更值得先尝试。
